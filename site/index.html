agent 86 desktop

The agent86 coding agent as a desktop app. The agent runs inside the app: no separate binary, server, or browser to set up.

Download the latest release View on GitHub

Windows 10 and 11 · macOS (Apple silicon and Intel) · Linux · MIT licensed

What it does

Threads in tabs, in parallel

Each thread works in its own workspace folder, with streamed answers, thinking, a context meter, / commands, and @ file mentions. A tab that needs you says so, and a notification tells you when a background thread is waiting or a long turn ends.

Tool cards with diffs

Every tool call shows its arguments and result, and edits show as diffs. Files on a card can be opened or revealed in Explorer or Finder; programs and scripts are only ever revealed, never run.

Approvals, behind your say-so

Every file write, command, and snippet asks first, with the diff or the command in front of you. Raise a limit when a turn hits one, and switch a thread between ask, auto, and read-only from its header.

Forms and questions

The agent can draw forms, choices, and confirmations (agent86UI, in Google's A2UI format) and ask you questions through a form, always inside a frame marked as drawn by the agent, so it never looks like the app's own prompts.

A Markdown viewer

Documents the agent writes open rendered beside the conversation, from a tool card or a link in its reply, with contents, Raw view, link following, and refresh. Images are never loaded and raw HTML never runs.

Any model, per thread

OpenRouter, Anthropic, OpenAI, Google, Ollama, vLLM, and other OpenAI-compatible servers. A thread's header switches its model from each provider's own list. Keys live in the OS keyring, never in a settings file.

Sessions and memory

Sessions are saved to the database the agent86 CLI uses, listed in the sidebar, and can be reopened and renamed. A memory panel shows and pins what the agent remembers.

Secrets stay out of the chat

Hand over a key in a masked prompt; the model sees only ${secret:NAME}, and the value reaches tools as an environment variable. A secret remembered for a project loads in later threads, in the app or the CLI.

Skills, sub-agents, and MCP

A project's own skills, specialists, and MCP servers load once you review and trust them. Sub-agents' work, including isolated runs in git worktrees, shows on their delegation's card.

Logs, tokens, and cost

A Logs view shows the agent's activity, with tokens, cost estimates, and tool calls for each turn, beside the app's own log.

The agent, built in

The agent runs in-process on agent86-core, with the same workspace jail, sandbox, guardrails, and secret vault as the CLI. Nothing else to install: no Node, no agent86 binary, no bridge.

A proper desktop app

Light and dark themes, keyboard shortcuts, an optional tray icon with the running turns, a remembered window, a single instance, and updates from GitHub Releases.

Install

Download the installer for your system from the latest release. The app updates itself from then on.

System File
Windows 10 and 11 Agent 86_<version>_x64-setup.exe (for you only, no admin prompt), or the .msi for all users
macOS, Apple silicon Agent 86_<version>_aarch64.dmg
macOS, Intel Agent 86_<version>_x64.dmg
Linux .AppImage (any distribution; updates itself), or .deb / .rpm

Then

1. Set up a model

On first launch, import your agent86 CLI settings (~/.agent86/config.toml), or pick a provider, a model, and (if it needs one) an API key. Test checks all three.

2. Open a thread

New thread (Ctrl+T or ⌘T) asks for a workspace folder. The agent works only inside it, and commands run in agent86's sandbox.

3. Ask

Type a task, mention files with @, and approve each change as it comes. Open more tabs to run threads side by side.

The installers are not code-signed yet, so Windows SmartScreen and macOS Gatekeeper warn on first launch; the user guide shows how to get past them.

Works with the agent86 CLI

The app embeds the agent through agent86-core, the same library behind the agent86 command line, with the same workspace jail, approvals, sandbox, guardrails, and secret vault. It stays compatible with the CLI where that matters:

  • The same API keys, in the same OS keyring entries: a key set with agent86 keys set <provider> works in both
  • The same session and memory database (~/.agent86/memory.db), so a session started in one opens in the other
  • The same per-project remembered secrets
  • A one-time import of ~/.agent86/config.toml on first run; after that, the two keep their own settings
