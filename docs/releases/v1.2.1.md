## Documents from chat links, and refresh

A document the agent writes can now be opened from its reply.

- **Click to read.** A link in a reply to a Markdown file in the workspace opens it rendered, in the
  pane beside the conversation. So does a Markdown path in code, such as `docs/plan.md`. A link to
  any other file opens it in its default app, with the same rules as **open**. `file://` links work
  too, in replies and in the viewer.
- **The agent links what it writes.** The app asks the agent to link each document it writes or
  updates, as `[title](path)` relative to the workspace.
- **Refresh.** **↻** in the pane reads the file again, for a document the agent is still writing; it
  keeps your place, Rendered or Raw. A file that could not be read yet is tried again.
- **Same rules.** Only files in the thread's workspace (or a worktree its sub-agents kept) open;
  anything else is refused, and the reason is shown beside the link.

Not yet: reloading a changed file by itself (click **↻**).
